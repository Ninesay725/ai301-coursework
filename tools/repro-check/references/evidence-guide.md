# Evidence guide: where proof lives in a reproduction package

## Environment

- Where it lives: Eval issue context and the repro report's environment record; live issue body, thread, and draft setup notes.
- What good looks like: Relevant versions, platform, dependencies, and settings identify the tested setup. Differences from the issue's setup are stated.

## Steps

- Where it lives: Eval repro report's setup, inputs, actions, and commands; live draft instructions and referenced public files.
- What good looks like: Starting state through trigger is rerunnable, with necessary input contents and prerequisites available. A stranger need not invent missing actions.

## Behavior shown

- Where it lives: Eval issue context against report output, logs, screenshots, and test results; live issue description against artifacts included or linked in the draft.
- What good looks like: Artifacts connect the relevant trigger to the claimed behavior. For cannot-reproduce, show the attempted operation and its output, with conditions not reached named explicitly; installation or startup alone is insufficient.

## Honesty

- Where it lives: Eval claim and report conclusions alongside their artifacts; live draft claims alongside quoted results and setup.
- What good looks like: Conclusions match observed scope. Untested conditions and differences are acknowledged; partial evidence does not become a universal claim.

## Comms

- Where it lives: Eval claim, issue context, thread highlights, and repo-facts policies; live comments, README-linked contribution docs (including docs/CONTRIBUTING.md), reporting templates, repository policy, and scope house rules.
- What good looks like: The claim names an issue-specific check. Read the policy itself: a stated issue-comment disclosure requirement needs the tool and extent named in the package. In course evals, do not infer unassisted authorship from absent disclosure. A missing policy or PR-only rule does not require issue-comment disclosure.
